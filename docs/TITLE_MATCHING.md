# 标题匹配规则

[返回首页](../README.md) · [使用手册](USAGE.md)

程序通过固定代码决定哪些来源 BibTeX 可以汇总，不调用 AI，不生成匹配置信度或准确率。

## 两道标题条件

1. **搜索阶段**：只考虑与输入标题一致的候选。没有同名候选就换来源；多个不同下载地址同名时记录歧义并换来源。重复返回同一个下载地址不算两个记录。不使用首条或相似结果兜底。
2. **下载阶段**：读取实际响应中的 BibTeX 标题，再与输入比较。输入有标题时，标题缺失或不一致都拒绝汇总；即使 DOI、arXiv 编号、DBLP 记录链接或缓存返回了可解析的 BibTeX，也必须通过此条件。

每个搜索来源最多返回 5 个候选；“唯一”只指本次返回的候选中没有多个不同的同名记录，不代表数据库中或其他来源绝无同名文献。

拒绝后继续已启用的其他来源；全部失败则将原始输入列入 `failed.bib`。从 2.0.2 起，默认 `merged.bib` 也保留并明确标记该输入，避免丢失引用键；被拒绝的下载响应不会用于导出。`downloaded.bib` 始终只含成功条目，取消“保留未抓取条目的输入内容”也可让合并文件只含成功条目。失败状态及实际响应、地址、时间和原因仍保留在日志及完整抓取包中。

## 哪些差异可以忽略

- 普通文本大小写、连续空白和末尾一个句点。
- BibTeX 保护花括号、已知 LaTeX 展示命令以及加粗／斜体等 HTML 展示标签。
- HTML 字符实体，以及 Unicode 组合字符的标准等价表示。

数字、副标题、重音、连字符、加减号、上下标和其他关键符号保留。`C++` 不等于 `C`，`Model 2` 不等于 `Model 3`，`A-B` 不等于 `A B`。TeX 数学片段及其中大小写保留；未知 TeX 命令和未知 HTML 标签不会直接丢掉。

规则偏保守。不同的公式编码、排版标点或正式版改题可能导致同一篇文章未匹配；程序不会猜测两者语义相同。该规范化仅用于比较与查询，不能修改保存的来源 BibTeX。

## 没有输入标题

只有 DOI、arXiv 编号或 DBLP 记录链接的输入仍可直接抓取。此时没有参照标题，日志显示“无输入标题”，成功条目的 `title_match` 为 `not_checked`，不显示“标题一致”。没有可用标识和标题的条目失败。

## 查看原因

界面日志展示输入标题、下载标题、用于比较的两个标题以及来源响应链接。成功详情显示是否执行了标题比较。完整包中的 `process.jsonl` 和 `results.json` 保留相同记录。

标题一致只能证明满足上述字符串匹配规则，不能证明作者、年份、页码或发表版本正确。程序仍不执行这些字段的核验或跨来源拼接。

## 旧任务

替换源码后需要关闭旧服务并重新启动，只刷新浏览器不会重新加载后台代码。界面会读取服务支持的匹配规则；旧服务尚未加载新规则时显示重启提示，暂不提供开始抓取操作，历史结果仍可查看和导出。

升级不会改写历史成功条目，也不会把它们标记为已匹配。继续旧任务只处理未完成或失败的条目，可能同时包含新旧规则的结果；每条是否执行标题比较以记录字段和日志为准。

要让整个文献库使用新规则，请重新导入原始 `.bib` 建立新任务。使用响应缓存也会重新执行下载阶段的标题比较。
