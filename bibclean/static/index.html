HOW IT FETCHES

从输入到汇总

  1. 读取所有条目。输入 .bib 文件或粘贴文本，程序解析文章列表并保留输入顺序。单次支持 3,000 条、5 MB。
  2. 优先使用已有标识。arXiv 编号直取 arXiv BibTeX；DOI 依次尝试 Crossref、DataCite；DBLP 记录链接直取 .bib。
  3. 再按标题搜索。依次请求已启用的 Crossref、DBLP、arXiv，每个来源最多取 5 个搜索结果。只选择标题一致的唯一记录，没有同名结果或有同名歧义时继续下一来源，不取首条兜底。
  4. 检查下载后的标题。输入提供了标题时，所有下载路径都必须让来源 BibTeX 的标题与输入一致，缺失或不一致就继续下一来源。仅统一大小写、空格、展示格式和末尾句点，保留数字、关键符号、副标题及公式。只有标识符、没有输入标题时，日志会明确显示未进行标题比较。
  5. 汇总并选择导出格式。默认沿用输入引用键，并自动处理 LaTeX 兼容格式。导出时可取消 URL，或按缩写表替换期刊／会议名。重复引用键添加后缀，原文另存。 默认保留未抓取条目的输入内容并标记来源，避免丢失引用；取消对应勾选后只导出抓取成功条目。

日志来自实际执行过程。搜索结果、选择规则、HTTP 请求、响应状态、等待、重试、跳转及下载内容都可查看。默认关闭缓存；启用后会明确标记缓存命中和原抓取时间。

程序执行检索、标题匹配与下载，不评估文献真假，不做评分或人工审批。标题匹配不代表作者、年份和版本已核验。来源响应原样保存，被拒绝的响应也可在日志中查看。

导出内容
merged.bib 完整合并结果
downloaded.bib 仅抓取成功条目
export-summary.json 导出数量与每条内容的来源
entries/ 每条未经改动的来源 BibTeX
failed.bib 抓取失败或未处理的输入条目
process.jsonl 完整过程日志
responses/ 实际 HTTP 响应正文
key-map.csv 输入键、来源键与导出键

导出选项对已有任务即时生效，无需重新抓取。取消 URL 只移除合并文件中的 url 字段，保留 DOI。缩写按固定全称／别名表处理 journal、journaltitle 和 booktitle，未匹配名称原样保留。缩写直接写成 booktitle = {CVPR} 这样的文本值。重复缩写键以最后定义为准：TOG 使用 ACM TOG；The Visual Computer 全称使用 TVCOMP 的 Vis. Comput.。完整包中的 formatting.json 记录每次字段调整。

合并预览、BibTeX 下载和 ZIP 中的 merged.bib 都自动处理 LaTeX 兼容格式，无需额外勾选： 将 June／July／Sept 等月份写为文本值，将重音字母写为带保护括号的 TeX 命令， 并转义普通文本中的下划线等特殊字符。已有数学公式与 URL／DOI 标识保持原样。 条目详情、entries/ 与 responses/ 仍提供抓取原文。

停止后可继续未完成条目；再次抓取会重试失败条目。旧版本已成功的记录不会自动重新检查标题，需要重新导入建立新任务。来源设置用于新建任务，导出选项会在当前浏览器记住。当前任务和日志保存在本机用户数据目录，实际路径会在启动窗口显示；刷新页面后可从左侧打开历史任务。
